الأشكال الثلاثة للردود

SHAPE 0

ردّ فـارغ

كلمتان فقط: ok. تُستخدم في بداية محادثة بلا مهمة، أو للتنبيه على تسمية الجلسة.

SHAPE A

عمل جديد أو إجابة

ملف كامل بـ ### FILE: أو تعديل بـ ### EDIT: أو أوامر جاهزة للتنفيذ، مع عنوان وملاحظات موجزة.

SHAPE B

طلب معلومات أولًا

عندما لا يُعرف محتوى ملف — يطلب cat أو ls فقط، ولا يقترح أي تعديل حتى يرى الناتج.

المفاهيم الأساسية

### FILE: ملف جديد

محتوى ملف كامل بمسار نسبي من جذر المشروع. يُنشئ الملف من الصفر.

### EDIT: تعديل جزئي

زوج واحد FIND / REPLACE فقط. يتطلب رؤية الملف سابقًا كاملًا عبر cat.

### DELETE: حذف ملف

حذف ملف مفرد فقط — لا مجلدات، ولا ملفات نظام أو أسرار.

## commands أوامر

سطر واحد لكل أمر، بأعلام غير تفاعلية. تُنفّذ من الجذر أو بعد cd.

@output إعادة تغذية

عندما تحتاج الأداة ناتج أمر قبل الاستمرار. تُكتب في سطر مستقل وتُقرأ لاحقًا.

ملفات السياق

AGENTS.md وDESIGN.md في الجذر — تُقرأ أولًا وتُلزِم كل القرارات اللاحقة.

مثال عملي مصغّر

مسار العمل المعتاد لإنشاء مكوّن جديد في مشروع Next.js:

# 1) الأداة تطلب رؤية ما هو موجود
ls
cat package.json

# 2) الذكاء يردّ بـ Shape A يحتوي
### FILE: frontend/components/Hello.tsx
## commands
npm install lucide-react --save

# 3) الأداة تُنفّذ: تُنشئ الملف، تُثبّت الحزمة
# 4) تراجع النتيجة، وتُكمل إن احتاجت

قواعد الأمان

  • ✓
    مسارات نسبية فقط لا مسارات مطلقة، ولا .. خارج جذر المشروع.
  • ✓
    لا أوامر مدمّرة منع rm -rf، shutdown، وكل أمر تدميري.
  • ✓
    لا خوادم تطوير npm run dev وnext dev وvite لا تُقترح تلقائيًا.
  • ✓
    لا تعديل بدون رؤية لا ### EDIT: على ملف لم يُقرأ كاملًا عبر cat في نفس الجلسة.
  • ✓
    احترام ملفات السياق قراءة AGENTS.md / DESIGN.md قبل أي قرار تصميمي.
